# Chat 模式与消息分支设计

状态：2026-10-25 用户确认设计并授权正式实施。本文记录产品契约；实现与验证进度见文末，不能把设计条目当作已实现功能。

## 1. 范围与共享边界

- Astrion 提供平级 Chat / Agent 入口。
- Chat 不创建工作区、容器、终端、子智能体或持久执行环境。聊天记录、媒体、草稿和记忆持久保存。
- 消息树仅用于 Chat。Agent 仍为线性历史，文件修改和真实执行状态不随消息分支回滚。
- Chat 与 Agent 共用模型协议、智能体循环、工具循环、对话文件读写和显示基础能力；禁止复制一套循环。
- 分支系统负责把本次选定路径转换为标准线性消息，再交给循环；循环不负责遍历树或选择分支。新增消息的分支归属也由分支／存储层处理。
- 共用循环不等于创建完整 WebTerminal。Chat 只装配模型、消息、工具分派和会话状态所需的轻量资源。
- 不自动提交、推送、部署或发布安装包。

## 2. 入口、路由和设置

- 侧栏顶部始终保留固定高度的一行：收起时左侧显示 `panel-left` 展开按钮，展开时按钮随侧栏边界向右移动并换为 `panel-right`，左侧腾出的位置显示当前 Chat / Agent 名称及下拉箭头。删除原「对话记录」导航按钮；其余导航图标在展开/收起过程中保持原坐标。顶部行高 40px，上方留白 12px、下方留白 8px；上方针对实体边界增加留白，以视觉平衡为准，不再要求上下数学等距。
- 展开菜单选择模式，Agent 在上、Chat 在下，当前项打勾；每个选项下方显示小字：Agent「规划、执行和交付」、Chat「交流、学习和探索」。顶部模式名称 18px，菜单宽 224px、选项高 52px；菜单内主名称 15px／字重 600，说明小字 12px，明确区分主次层级。
- 使用现有三主题、图标和自定义组件，不采用并排分段切换器。
- Chat 路由：`/chat`、`/chat/new`、`/chat/<id>`；Agent 原路由保留。
- 新建只进入空页，首条消息发送时才创建对话文件。未发送媒体属于草稿。
- Chat 历史属于认证用户，与工作区无关；Chat 搜索只搜索 Chat。
- 模型选择、思考和推理强度的位置保持不变。
- 图片／视频直接从本地选择，支持粘贴与拖拽；不出现工作区媒体选择。
- 不支持普通文件上传／发送，包括 PDF、Office、代码文件、文本与 ZIP。
- 隐藏输入栏左下方的版本控制按钮，以及权限／沙箱、工作区、目标、子智能体、终端等 Agent 专属入口。
- Chat 不挂载审批面板或审批恢复控件，审批状态不得占用输入栏布局；不能以默认折叠代替移除。
- 保留 Token 环与现有 hover 信息，Chat 点击不打开弹窗；圆环分母使用 Chat 独立深压缩阈值，不读取 Agent 的压缩设置。缺少最终 usage 的停止请求不得记作零消耗或虚构精确统计。
- 原计划／询问／执行的位置改为联网开关，点击直接切换。
- 共享账号、提供商凭证、模型目录、模型可见性、主题和语言；Chat 独立默认模型、思考／强度、联网默认值和专属个人指令。设置页移除「默认开启思考」选项，当前对话顶部思考切换保持独立。
- Chat 设置页使用既有 `ModelSelectDropdown`、`FancyCheck` 和共享设置行／输入框／文本域／按钮／反馈样式，不维护专属样式。推理强度从 Agent 的 `ModelPrefTab` 提取为 `SettingsChoiceDropdown`，两边共用组件、原浮层定位和完整选项（默认、low、medium、high、xhigh、max），不额外添加 minimal 或过滤 max；Chat 默认设置、对话配置和任务受理的校验均引用 `config.limits.REASONING_EFFORT_LEVELS`。Chat 不借此创建 Agent 运行资源。
- 全局记忆和专题记忆由智能体自行维护，不在用户设置页显示查看、添加、编辑或删除入口；设置页不请求记忆管理接口。既有记忆数据、内部工具和注入机制保持。
- 默认配置影响新对话；当前对话的选项影响其后续请求。切换分支不回滚真实个人配置与记忆。
- Chat 首轮复用 Agent 的后台标题生成，读取账号 `preferences_dir` 中的 `auto_generate_title`／`title_model`，尊重对话 `skip_auto_title_generation`。Chat 首条 user 已在受理时保存，需按首轮身份判定，不能套用 Agent 的空历史条件；重生成、分支续聊和压缩续接不重复起标题。标题客户端保留提供商静态头，并使用原 Chat 对话稳定会话 ID 与账号请求头开关，不读取 Chat 存储根偏好。
- 桌面标签沿用现有外观，不添加 Chat / Agent 区别标识；内部明确区分身份，仍由统一标签管理器管理。
- Chat 桌面和手机侧栏的「个人空间」「个性化」均通过 `personalization.openDrawer(tab)` 打开共用 `PersonalizationDrawer`，保留页签参数，不能跳转到 Chat 设置页；Chat 自己挂载同一个弹窗，打开时手机侧栏先收起。「设置」入口仍进入全屏设置页。
- 顶部栏与 Agent 一致：开启思考且模型支持时，推理强度未指定显示英文 `default`，指定档位显示 low／medium／high／xhigh／max；不使用「默认」或「自动」的翻译。
- 设置返回原 Chat / Agent 页面。关闭标签不停止后台生成。

## 3. 消息树与编辑契约

参考上传 Open WebUI 源码的 parentId / childrenIds / currentId 思路，以及已验收原型；正式存储沿用 Agent 对话文件模式，消息格式不另造一套。

| 操作 | 结果 |
| --- | --- |
| 用户编辑后保存 | 原地修改，不创建节点或分支，不自动生成，保留后续 |
| AI 正文编辑保存 | 原地修改，不创建节点或分支，保留后续 |
| 用户编辑后发送 | 创建兄弟用户节点，再生成回复，旧分支保留 |
| AI 重新生成／手动重试 | 创建 AI 新版本，保留旧版及失败记录 |
| 查看旧分支 | 只改变临时查看位置，不改变最新分支 |
| 在当前查看路径发送新消息 | 受理后立即成为最新分支，不等待 AI 完成 |
| 刷新／再次加载 | 始终打开最新创建／继续的分支 |
| 对话搜索 | 仅最新分支的完整路径正文，包含共同祖先，不搜旧分支独有内容 |

- 分别维护最新分支归属和临时查看游标，不照搬原型持久恢复上次查看游标的行为。
- 生成绑定固定回复节点，查看切换不能改变写入归属，完成也不能抢回当前视图。
- 原地编辑共享祖先节点会修改所有引用该节点的路径；不自动重生成原有后续。
- 一个 Chat 同时最多一个生成任务；生成时允许查看其他分支，草稿可继续编辑。发送／重生成需前一生成结束或停止。
- 工具循环中已经输出完成的模型正文允许编辑，不提供重新生成。正在流式生成的正文在结束或停止后允许编辑。
- 中间正文编辑按钮在消息区域右下角：桌面 hover／键盘聚焦显示，手机点击消息区域后显示；避免右上角遮挡首行。入口仅定位，不为正文添加额外底部占位，保持极简摘要上下间距。
- 最终回复沿用底部复制、编辑、重新生成和版本切换区域；tokens/s 同在这一行，替换共享消息组件的默认操作行，不额外叠加第二行。复制沿用共享正文提取和成功变勾反馈。
- 两种模式底部都使用 `MessageActions`／`MessageActionButton`，共用 Agent 原操作行与按钮样式，大小、hover、位置不能由 Chat 独立定义；Chat 只装配显示内容与行为。重新生成直接使用图标库原版 `refresh-cw.svg`，不旋转或改画。
- Chat 使用共享 `mergeAssistantDisplayRuns` 融合连续 assistant 展示节点，让极简与堆叠模式的思考／工具自然成组；不改写原消息树。正文 action 保留 `responseMessageId`，编辑按钮按它查找原节点，只有对应正文区域进入编辑，思考／工具仍保留。最终操作行使用融合后末节点的版本身份。
- 思考结束、工具完成和结果持久化不得改变用户展开状态。Chat 适配层按明确的 responseMessageId／工具调用别名保留消息、思考和工具的显示身份；页面为当前对话保留身份映射，切换对话即清理，避免快照替换及下一轮请求重建摘要分组。不添加 Chat 专属自动收起规则，继续使用 Agent 的共享展开组件。
- 持久化工具适配遵循 Agent 的 `intent_full`／`intent_rendered` 字段，工具展开标题沿用 intent 设置；不要另填 `tool.intent` 导致重复显示意图或回退到摘要状态文案。
- 编辑只修改模型正文，不破坏 message_id、tool_calls、tool_call_id、工具结果及关联元信息。后续模型请求读取更新；已发出的请求和已发生的工具操作不回滚。

## 4. 工具与联网

Chat 只有以下 9 个模型工具：

1. `web_search`
2. `extract_webpage`
3. `manage_personalization`
4. `update_memory`
5. `search_chat_memory`
6. `read_chat_memory`
7. `update_chat_memory`
8. `search_chat_history`
9. `read_chat_history`

- 不注入文件读写、终端、计算器、媒体查看、MCP、子智能体、工作流或技能加载工具。
- 图片／视频以正常多模态消息提供，不把本机文件路径当作模型已经看过的内容。
- 联网关闭时服务端拒绝搜索和网页提取，不只修改按钮或提示词。
- 切换联网状态通过前端隐藏的 user 消息通知模型，不产生可见气泡、消息分支或单独生成；在下一次模型请求前送达。
- `manage_personalization` 只允许共用偏好和 Chat 配置，不允许修改 Agent 执行权限默认值。
- 历史检索／读取遵守最新分支范围，不把整树其他版本混入结果。

## 5. 系统提示词

Chat 独立装配以下部分：

1. 基础身份、模型身份、交流和信息准确性规则。
2. 九工具的用途与调用约束；完整参数放 API tools 定义。
3. 消息内图片／视频的多模态分析规则。
4. Markdown、引用、show_ui／show_html 等适用的输出规则。
5. 个人基础偏好与 Chat 专属个人指令。
6. Chat 独立全局记忆正文和专题记忆索引。
7. 日期、时区、初始联网与必要会话状态。

不注入工作区、项目规范、AGENTS.md、技能目录、权限／执行模式、子智能体、工作流、修改留痕或终端操作说明。

- user／assistant 历史、tool 结果、隐藏联网 user 通知属于正常上下文，不冒充 system。
- 分支实现与 UI 控件行为由应用保证，不靠大段系统提示词解释。
- 两层记忆均与 Agent 隔离。全局记忆由 update_memory 维护并注入；专题记忆按索引搜索和读取。
- 记忆／个人指令更新影响后续请求，不因切回旧分支而回滚。

## 6. 暂停与显示补齐：Chat 和 Agent 共用

- 正在输出正文／思考时停止：保留后端已收到的有效内容，保存并标记 stopped。
- 尚无有效内容时不创建空白回复。
- 半截工具名称／参数不提交；工具执行临时内容不作为成功结果保存。
- 已提交完整调用保留协议配对，真实完成结果保留，未完成调用补取消结果。停止不能撤销已发生的文件操作。
- 仅保留 API 实际返回的可展示思考；未完成协议专用 reasoning 块不能伪装成有效块续传。
- 前端进入停止收尾态，后端停止并提交后发布最终快照，前端一次性显示缓冲差额，不慢放积压文字。
- 最终快照保持稳定消息／任务身份、绝对事件游标和导航所有权。不能从事件0重放、重复追加或写入其他对话。
- 必须覆盖 asyncio 硬取消收尾，不能只依赖下一块 SSE 检查停止标志。

## 7. 数据存储与压缩

- 数据归属用户：免登录 host 使用 DATA_DIR/chat；账号使用可信 personal/chat；尊重现有数据根优先级。
- 对话采用 Agent 的一对话一 JSON 模式，保留现有外层字段与消息格式，仅增加必要的模式／树关系信息。
- 原始消息树为权威，传给循环的单路径为投影；不能用路径覆盖全树，也不能保存两套互相漂移的正文。
- Chat 全局记忆、专题记忆、媒体、草稿与交接状态独立保存；不借假工作区存放。
- 媒体以稳定 ID 引用，原文件／元信息受用户身份校验；同一媒体可由多个分支引用。
- 旧分支仍引用的媒体不得按最新分支清理；未发送上传由草稿引用并做延后清理。
- 对话搜索索引只含最新路径；索引可重建，不是正文权威。
- 长对话摘要保存在会话数据中，绑定路径和覆盖版本；编辑覆盖区间使相应摘要失效。保留完整原树供搜索、回顾、导出。
- Chat 只支持深度压缩，设置页可独立设置「深压缩触发上下文」，账号偏好键 `chat_deep_compress_trigger_tokens`，默认 250000 tokens，整数范围 1000–2000000。通过 `CHAT_DEFAULTS` 和 `sanitize_chat_settings` 注册与校验；请求安全边界读取账号当前值，不继承 Agent 开关／阈值、不再按模型窗口的 75% 触发。Chat 工具完成钩子禁止浅压缩。
- 删除对话停止活动生成并清理其独占媒体，不删除已交接到 Agent 的材料，也不自动删除长期记忆。
- 自动流重连不增加分支；用户手动重试增加版本；写入型工具不能因重连重复执行。

## 8. Chat → Agent 交接

- 模型收到需求后，必须在回答、展开方案或调用工具之前判断是否需要真实文件、代码执行、交付文件或持续执行验证，不另起复杂度分类模型。
- 普通深入讨论、方案、代码示例不因复杂而升级；拒绝后同一任务不重复推荐。
- 符合条件时立即用一句简短的话说明适合交给 Agent，下一行输出专用标签并结束回复。禁止解释为何 Chat 不能做、列举能力限制或提供 Chat 替代方案／建议／步骤；禁止先口头询问或等待文字同意。标签必须写在回复正文，不放进代码块或转义；它不是工具或函数调用，不能调用不存在的切换模式／切换工作区工具。由固定组件渲染卡片让用户确认；标签不能指定目录或权限，不新增工具。
- 卡片30秒无操作或点击不切换：服务端一次受理，追加 user 消息“不切换到 Agent，继续在 Chat 中处理当前任务”并续接。
- 点击切换即停止自动拒绝倒计时并固定交接，刷新不重置期限、不重复发送。接口允许从 pending 直接 accept，不要求前端先 select。
- 交接不显示工作区选择、新建、名称或路径表单，统一使用可复用的专用默认工作区：本机 `~/Desktop/Astrion/Default`，云端每账号 `astrion-default` 项目。服务端创建／复用，不采用前端传入路径，也不更改用户侧栏设置的默认工作区。交接后需要换工作区时使用对话迁移，详见 `docs/conversation_transfer.md`。
- 用户同意后固定最新分支快照，后台追加总结请求生成交接摘要；与 Agent 压缩及 Chat 压缩共用 `utils/summary_request.py` 的请求流处理，不执行改写原历史的压缩流程。Agent 与 Chat 压缩复用各自现有 APIClient；交接独立客户端使用原 Chat 账号的 `preferences_dir` 和 `resolve_context_headers`，保留提供商静态头、会话头开关及端点限制，不读取目标工作区偏好。
- API 错误必须保留具体状态和原因，不能统一包装为空摘要；失败诊断写入 `LOGS_DIR/summary_requests.log`（脱敏、轮转，不记录请求头和消息正文），取消／失败／成功均关闭请求流。各场景仍负责自己的摘要指令、工具定义、计费和历史提交。
- 目标工作区保存 `.astrion/handoff/<交接ID>/summary.md`、`conversation.md` 及分支媒体。发给新 Agent 的交接消息统一使用工作区根目录下的相对路径；服务端读写使用真实路径，不能将其拼入模型消息或作为 Docker 的材料路径返回。
- 交接接口、Chat 首次快照和任务轮询中的交接状态统一经过 `handoff_view.py` 白名单序列化，不返回内部材料路径；Docker 同时移除选择状态的 `project_path`，过滤错误中的服务端绝对路径。新写入的材料位置也是相对路径；读取旧状态不回写原树。
- 摘要覆盖原目标、确认方案／限制／纠正、真实进展与验证、未完成事项、下一步和资料位置，不把讨论方案冒充已执行。
- conversation.md 是同快照的纯净 user／assistant 对话，过滤工具、system、隐藏通知、切换标签和内部总结请求。
- 成功后创建关联的新 Agent 对话并自动继续；使用 Agent 自己的 system／工具／权限，原 Chat 和消息树保留。
- 失败留在 Chat，允许重试向默认工作区交接，不创建缺少材料的空 Agent。
- 手动顶部切换 Chat / Agent 只是导航，不自动触发交接或转换会话类型。

## 9. 验证与交付

- 核心逻辑由主智能体编写；子智能体仅 low，用于定位／独立审查，禁止分派主要实现。
- 新回归位于 test/YYYY-MM-DD_功能/，不覆盖已验收原型测试。
