# 对话级 Git worktree

2026-11-14。本文记录已确认的产品契约及本轮实现。macOS 上的真实临时 Git、文件／命令和离线主子循环、API、前端回归已通过；UI 与其它平台的原生执行仍待实机验收。准确结果与命令见 `test/2026-11-14_Git工作树/README.md`。

## 启用与快照

- 设置项「Git worktree 启用」默认关闭，仅影响之后创建的 Agent 对话。创建时写入 metadata，缺失或非法字段按未启用处理，不为老对话迁移启用。
- 运行期间只读对话快照，不读最新个人设置改变工具能力。关闭的对话不注入专属 system、两个工具及前端工作树切换入口。
- 启用不强制使用工作树，允许在主目录修改。专属规则要求正式修改前询问是否在工作树分支中修改；用户已经明确说明（包括直接修改主目录），或已切到任务分支／工作树时不重复询问。
- 不单独描述搜索工具；统一表述文件操作和命令执行跟随当前执行目录。

## 位置、身份与环境

- 托管工作树位于当前工作区 `.astrion/worktrees/<name>/`，不放全局程序数据目录。配置 Git 忽略以免被提交，并避免主目录扫描递归包含其它工作树。
- workspace 身份、数据目录、对话存储、私有项目记忆归属保持不变。对话独立保存实际执行根、仓库、分支、起始提交与切换修订号；禁止复用会重写工作区身份或关闭终端的项目路径迁移方法。
- 文件操作、新命令和新建终端默认目录使用实际执行根。原生沙箱和固定权限继续生效，切换不能被当作完全访问授权。相对路径基准与工作区身份分别处理。
- 已经启动的终端进程、开发服务器和后台命令保留启动时的目录，不伪装成已搬迁。
- 非 Git 工作区应返回明确错误；不得自动 git init。Git 失败、路径失效和冲突不能退回主目录继续修改。

## 两个模型工具

### enter_worktree

只有已启用的对话可见和可执行。包含 intent 与 target；target 是互斥的 create/enter 对象。

创建参数全部必填：

- action = create。
- branch_name：完整合法的新分支名，例如 astrion/fix-login；不得强制重置已有分支。
- start_ref：明确起始分支、标签、提交 SHA 或 HEAD，不得省略。HEAD 相对当前执行环境解析，实际解析到的提交需固定。
- include_uncommitted：明确 true/false，不得省略。true 将当前执行目录的未提交修改（含未跟踪且未被忽略的文件）复制到新工作树，原修改保留。忽略文件不是隐含全部复制的对象。

Git 原生提供选择起点和创建分支；携带未提交修改由 Astrion 编排。选择其它起点后应用修改可能冲突，失败不改变当前执行绑定，不静默漏改或覆盖；报告残留工作树供后续处理。

进入已有参数：action = enter、branch_name。查找已存在的工作树并恢复现有内容，不重复应用起始版本或携带修改，不暗中创建其它分支。分支、目录和仓库归属需校验。

### exit_worktree

只有 intent 参数。将当前对话执行绑定返回工作区主目录，不切主目录当前分支。工作树、分支、提交、未提交修改全部保留；已经在主目录时返回实际状态。

不提供合并工具。提交、合并、冲突处理和验证由智能体通过既有命令能力逐步完成；退出不隐含提交、合并或删除。

## 用户入口与原子切换

- 用户点击 Git 状态栏当前分支打开工作树选择入口；可创建、进入、退出，不把重命名分支混同于切换执行绑定。
- 用户手动切换只允许主智能体空闲，前后端均校验。空闲仅指主智能体，不因子智能体、后台命令或终端服务仍运行而禁止。运行中拒绝，不排队切换。
- 模型通过工具切换应在独立安全工具批次执行，不能与文件操作并行，不能使同批操作跨两个根。
- 切换成功后提交执行绑定，再发布通知。失败不显示为成功。读取状态不创建对话或改变绑定；显示加载仍用唯一 bootstrap，异步响应遵守导航所有权。
- /new 预选在首次消息创建时生效，真实对话首个 system 直接包含实际环境；空页不因选择而制造空对话。

## 提示词冻结与通知

- 完整初始 system 两次压缩间保持冻结，不因切换重写。
- 主智能体自己切换以工具结果告知；用户对已创建对话手动切换，复用已有 user 通知机制。
- /new 首消息前已经选择工作树的主智能体，在初始 system 写实际绑定，不能先冻结主目录再补切换。
- 新创建子智能体初始 system 写父对话当前工作树与执行目录。
- 已运行子智能体收到 user 环境变更通知，在当前完整工具批次真实回填后更新后续执行绑定，不能插入 assistant/tool 配对中间。
- 空闲子智能体保存待同步修订，下次主智能体发消息时附带 user 环境变更信息并应用；不单独唤醒模型请求。创建之后的再次切换同样用 user 通知。
- 绑定、修订与待同步信息需持久化，恢复不能误回旧目录。子固定权限档位与工作区身份不扩大；内部目录资源独立装配，不临时修改父实例资源。

## 实现接线

- `modules/git_worktree/` 按 Git 服务、携带修改、绑定、主通知、子同步、只读查询与跨平台命令封装分层；生产非 Local 后端明确拒绝，禁止使用控制端目录替代。
- `server/status/worktree.py` 提供读取与仅主任务空闲时切换的接口；`server/context/new_conversation.py` 在首消息创建前准备绑定，普通空页选择不创建工作树。
- 执行根仅影响相对原生文件操作、前台／后台新命令和新终端。技能与项目记忆仍属于原工作区。模型结果在根偏移时返回实际绝对路径；编辑记录／预览保存工作区相对路径，bootstrap 仍按原工作区解析这些产物。
- 状态栏 Git 查询跟随当前绑定；目录或 Git 记录损坏时保留分支与返回主目录入口，不显示主目录差异。对执行端配置的容器挂载点（默认 `/workspace`）／WSL Git 管理路径做受限映射，映射后的管理目录必须位于当前工作区 `.git/worktrees/` 内且不能重定向。
- 主通知落盘成功后才清除待通知记录，确认失败按切换修订号去重重试；子同步在安全点持久化通知后应用执行根，保留原固定写权限。
- 携带修改保留 staged／unstaged 分层，未跟踪文件复制不覆盖目标，并核对复制内容。失败保留分支／目录及恢复信息；临时补丁清理警告不掩盖原始冲突。

## 保留与验证

暂不实现自动清理、数量上限或删除联动。容器创建的 Git 链接含容器绝对路径，Git 工作树维护命令应在原执行环境运行；宿主侧 `git worktree prune` 可能将这些链接误判为失效而移除管理记录。切换 host／Docker 部署或修改挂载点不包含已有 Git 链接的自动迁移。退出／关闭对话不删除工作树、分支或进程。Git 只把提交存入版本历史；未提交内容仍依赖磁盘文件保留。

需覆盖真实临时 Git 仓库的创建、起点、二进制／删除／新文件携带、冲突、重入、退出、路径与分支校验；快照默认关闭和老对话不迁移；工具可见性及执行守门；主任务互斥；子批次切换和 idle 延迟同步；初始 system 与后续通知；前端导航所有权。测试使用隔离数据，不改真实仓库分支或真实对话。
