# 定时任务设计与实现契约

本文件记录 2026-11-16 对话中已确认的产品决定，是正式实现、后续修改和回归的共同依据。设计稿在 `_experiments/scheduled-tasks-demo/`；正式界面遵循根目录 `DESIGN.md`。不得将演示数据、模拟运行或静态页面冒充真实调度。

## 范围与生命周期

- 首版只支持 Agent，适用于日报、提醒、项目维护；不支持 Chat、文件变化、webhook、应用启动等事件触发。
- Astrion 关闭窗口后继续驻留并执行计划；用户真正退出应用、后端进程结束、电脑关机后停止。首版不提供关机执行或远端执行端。
- 复用既有单后端进程、RuntimeService、TaskManager、主任务门闸、对话存储、目标模式、工具审批、费用和显示事件。不得另外启动一个操作相同数据目录的 full/headless 后端。
- 用户级计划库：同一用户可以管理其全部计划，创建来源对话仅作追溯；用户之间隔离。计划 ID 只是标识，不是授权凭据。

## 计划与配置文件

采用 YAML（也接受对应 JSON）与 `schema_version: 1`。Agent 先写文件，再提交验证并入库；数据库中的记录是唯一权威，修改原文件不会自动更新计划。

```yaml
schema_version: 1
name: 每日项目巡检
enabled: false
schedule:
  type: daily
  timezone: Asia/Shanghai
  times: ['09:00']
target:
  workspace_id: workspace_id_here
  conversation:
    mode: new
message: 检查项目状态，汇报需要处理的问题。
configuration:
  mode: inherit
goal:
  mode: off
policies:
  busy: skip
  missed: skip
notifications:
  enabled: true
```

- `id`、`revision`：新建可省略；覆盖必须显式提交现有 ID、当前 revision 和覆盖意图。名称不作覆盖依据。错误配置、资源不存在或版本冲突不得修改旧记录。
- `name`、`message`：非空；名称最多 80 字符，指令是正常 user 消息。
- `target.workspace_id`：可省略，提交时解析为工具所在对话或页面显式选定的工作区，并保存固定 ID。不得在触发时读取前台工作区而漂移。
- `target.conversation.mode`：`new` 或 `existing`。已有对话需要 `id`，提交与触发时均校验它属于所选工作区、属于当前认证用户；不允许 Chat ID。
- `configuration.mode`：`inherit` 或 `custom`。已有对话默认沿用执行当时的配置；新对话在保存计划时解析并保存默认配置快照。custom 可设置 `model_key`、`thinking`、`reasoning_effort`、`work_mode`、`permission_mode`、`execution_mode`、`network_enabled`、`ask_user`，以及明确的工作树目标。字段、模型能力和权限组合必须经过既有规则校验，不静默降级或扩大权限。
- `configuration.ask_user`：是否允许模型询问用户，仅 custom 可设，缺省为不允许。工作模式为执行或计划、目标模式关闭且未允许时，每次运行会紧跟指令附带一条隐藏 user 消息（`source: runtime_notice`，前端不显示），告知模型用户不在场、不要调用 `ask_user`；不改动工具或工具类别的启用状态。询问模式由后端自身禁用 `ask_user`，目标模式的注入语已禁止交互，沿用对话配置时不附加任何约束。
- `goal.mode`：`off`、`start`、`continue`；继续只能用于指定已有对话。可选正整数 `max_turns`、`max_tokens`，缺失表示不限制。沿用现有目标模式规则。
- `policies.busy`：`skip`（默认）或 `merge`；`policies.missed`：`skip`（默认）或 `latest`。
- `notifications.enabled`：是否发布运行完成／失败通知；执行结果与通知投递结果分别保存。
- 拒绝未知字段、非法类型、重复 YAML 键、非有限数值和过大配置，避免拼写错误被悄悄忽略。配置来源、文件路径和可信身份分开保存。

## 时间规则

统一使用 IANA 时区；保存和调度比较使用 UTC 时间点，界面使用计划时区显示。

| type | 额外字段 | 行为 |
| --- | --- | --- |
| once | date: YYYY-MM-DD；times: [HH:mm] | 单次指定时间，处理后自动停止 |
| interval | every: 正整数；unit: minutes/hours；可选 anchor | 按保存的 UTC 锚点固定间隔；首个触发为 anchor + interval，不随每次完成时刻漂移 |
| daily | times: [HH:mm, ...] | 每天固定时间 |
| weekly | days: [0..6]；times | 0 为星期日，1 为星期一 |
| monthly | day: 1..31 或 last；times | 无该日的月份跳过；last 为每月最后一天 |
| cron | expression: 标准五字段 | 支持通配、列表、范围和步长；DOM/DOW 同时受限时按 OR |

夏令时不存在的当地时间跳过；重复当地时间仅采用第一次出现，不重复运行。时区、下一次与未来三次时间均由后端计算，浏览器不维护第二套权威调度算法。高级 cron 不支持秒字段与事件触发语义。

## 触发、并发、漏跑与恢复

- 计划、触发实例（occurrence）与运行记录持久化在运行态数据根内的 SQLite；同用户跨工作区查询不会创建执行实例或选择工作区。
- Rust 与旧版 Python 都通过各自的 Runtime 提交定时 Agent 指令。Rust 在同一任务准入锁中复核目标对话、工作树、权限与已有活动，复用普通任务的工具审批、等待问答和目标执行。
- 新建定时 Agent 对话时读取当时的「默认启用内置浏览器工具」设置，不锁进提交计划时的配置快照，也不覆盖已有对话设置；仍由正常的平台可用性与工具权限规则决定可以使用哪些工具。
- 到期先原子认领并保存配置快照，再请求 RuntimeService。每次触发有稳定唯一键，多个轮询、立即运行、重复点击和并发调度不能重复受理同一实例。
- 同计划上一轮尚未结束、目标对话忙碌或后台工作者仍活跃：默认记录跳过；merge 只保留最近一次待执行，不无限排队。
- 主回复结束不等于整次运行结束；需结合子智能体、后台命令、通知续接和目标生命周期判断。
- 漏跑默认跳过；latest 在恢复后只补最近一次，不逐条重放离线期间所有触发。记录遗漏与处理原因。
- 进程重启后校准未完成实例，明确记为中断；不得推断已成功、悄悄重跑可能已经产生副作用的那一轮。
- 本轮失败保留记录，计划未来继续触发；调度器不默认重跑整轮。模型请求层和目标模式已有重试仍遵循各自契约。
- 更新只影响后续触发，已认领实例使用保存的配置快照。暂停／删除计划不取消已开始的运行；停止本轮为独立动作。
- 普通任务遇到审批或提问正常等待，发布可见的待处理状态；等待超时结束本轮，不自动扩大权限。目标模式沿用无人值守规则。
- 存储锁不跨越模型请求、执行资源装配或外部 IO；执行写入仍受主任务门闸保护。

- 侧边栏“工作流”下面是“定时任务”，使用上传的 timer 图标；进入独立 `/schedules` 页面，桌面标签导航同时登记。
- 应用侧栏折叠。无横贯顶部的大工具栏；页面底色使用 `--group-page-bg`，左侧列表和右侧编辑区都是同级的不透明卡片面板，使用 `--group-card-bg` + `--group-card-shadow`、R12、无描边。列表和编辑区各自内部滚动。
- 页面外边距为 16px（上下）／20px（左右），左右面板间距 16px；两侧面板内部以 16px 作为主要内边距轨道。左侧标题栏高 32px，标题栏与搜索区之间保留 16px；右侧标题、滚动内容和底部操作区保持同一水平内边线。
- 左面板顶部“定时任务”与新建按钮；按钮菜单“导入配置／新建计划”。搜索输入框常驻占满整行，工作区筛选另占整行。表单和操作复用公共 `UiMenu`、`UiSearchField`、`UiSelect`、`UiModelSelect`、`UiSwitch`，不再维护定时任务专用控件。
- 按“已开启／已停止”分组，可折叠并有高度过渡、箭头旋转；搜索和筛选不重置折叠状态。
- 视觉对齐以完整可见热区为准，检查图标按钮 hover 背景、搜索框外框、Select 触发器、Switch 轨道以及卡片阴影边界，不能只按图标或文字位置判断。窄屏保留紧凑覆盖值并改为单列布局。
- 默认直接显示计划设置。“运行记录／配置文件”放入右上角更多菜单，与复制计划、复制 ID、下载 YAML、删除并列；子页面保留返回入口。
- 时间、目标、模型／执行、目标模式、策略、通知等按任务语义组织；删除不帮助选择的说明和无意义字数统计。
- 所有开关有滑块和轨道过渡；菜单出现与关闭沿触发方向互逆，翻转位置时同步翻转动画方向。
- 对话各列表的更多菜单增加“复制对话 ID”；工作区管理增加“复制工作区 ID”。首版不为此新增模型可用的跨工作区枚举工具。

## Agent 工具与技能

- `submit_schedule(file_path, overwrite=false)`：通过执行端读取文件，验证后创建或按 ID/revision 原子覆盖。
- `query_schedules`：支持明确 ID、工作区／状态等筛选、字段投影、完整配置和运行记录；只读，不提供其他用户数据。
- `manage_schedule`：启用、暂停、删除、立即运行、停止明确的一次运行；运行控制与计划生命周期分开。
- 新增内置技能教 YAML、ID 获取、验证／覆盖及查询流程；工具 Schema 不塞几十个计划字段。
- 定时工具的权限分类、动态加载、结果 formatter／前端 renderer 统一登记；Chat 和子智能体不额外获得计划写权限。readonly 只能查询，plan 模式不能提交或运行。
