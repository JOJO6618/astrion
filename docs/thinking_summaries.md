# 思考内容摘要

2026-10-29 实现；初次按用户要求仅做语法检查，随后已按用户补充要求完成前端构建。实际效果、提供商请求和视觉由用户验收。

## 设置与范围

设置 → 通用 → 思考摘要模型／思考内容摘要。默认关闭，必须明确选择注册表中的一个模型才可开启，没有自动选择或其他模型回退。后端个人配置 `thinking_summary_model` 与 `thinking_summary_enabled` 双注册；空模型时启用状态归一为关闭。选定模型失效时不发起摘要请求。

开启后可修改「摘要生成间隔（秒）」，配置键 `thinking_summary_interval_seconds` 在后端默认与sanitize、前端表单类型／默认／读取均注册；默认20秒，整数范围1–3600秒，支持恢复默认。每个工作段开始读取一次，保存后从下一次任务生效；首次摘要固定3秒，不受此项影响。

Agent、Studio、Chat 共用 `server/chat_flow_stream_loop.py` 的接入层；主模型 `api_protocol == responses` 时跳过辅助摘要，保留原生摘要。辅助客户端使用关闭思考的快速配置，凭证及协议仍由统一 APIClient 处理，外部会话头沿用原对话和账号偏好。

## 生成规则

- 每次思考块首个片段到达起，至少 3 秒且累计至少 200 字符才发起首次请求。
- 后续距上次请求至少达到设置间隔（默认20秒），且新增至少500字符，两个条件同时满足。
- 同一思考块单飞请求，期间积累新增原文；每次发送待总结新增片段末尾最多2000字符。已跳过的更早内容直接消费，不排队补发，不重复发送上一请求已截取的原文。该上限只作用于当前思考原文，用户原始输入与此前摘要仍按原格式携带；完整思考的保存与展开显示不截断。
- 思考结束后，首次仍守 3 秒／200 字符；后续尚有至少 500 字符的剩余片段可立即补一次。更短的尾段不额外请求。
- 请求超时 30 秒；失败保留此前已显示的摘要，无摘要时保持原始思考首行。
- 正文和工具流不等待摘要请求；正常任务在发布完成事件前异步等待本工作段摘要收尾，确保前端停止轮询前消费最后一次更新。因此摘要尚未完成时，任务的完成状态可能稍晚于正文结束。
- 停止、异常与事件循环关闭时取消未完成摘要，不因页面切换取消。

系统提示词唯一文件：`prompts/thinking_summary.txt`。User 内容依次为固定开头“请为如下内容生成思考摘要”、本次工作原始输入、此前按生成顺序累计的摘要和当前新增思考原文。Chat 重生成从实际 user 节点读取原始问题，压缩续接继承本工作段输入与摘要。

中文以 8–12 字为目标、15 字为上限；英文 2–4 个单词；无标点、不强制加“正在”、不把思考计划冒充执行事实。服务端去除标点，中文超长或纯 ASCII 词数不符合要求时不发布，不硬截断替代。

## 显示与持久化

`modules/thinking_summary/` 负责调度、请求与独立显示存储。以实际 ConversationManager 的对话目录为根，存储位置为：

`<实际对话目录>/thinking_summaries/<conversation_id>.json`

沿用现有工作区、Studio namespace 和 Chat 账号存储隔离；文件包含版本号、按 response message ID 索引的最新摘要、revision、generation 及该思考块已发布摘要序列。每个成功发布的摘要先原子保存，再发 `thinking_summary` 任务事件；不写入对话历史、模型上下文、reasoning_content 或正文。

事件携带固定 response message ID、思考块 generation 与单调 revision。重试取消旧 worker 并清除其显示摘要，不允许旧代覆盖新代。保存完成释放目录锁后才发布显示事件，保持显示锁 → 存储锁的现有锁序。

统一 bootstrap 在脱离模型上下文的显示副本上装配独立摘要；运行投影按回复与 generation 定位思考动作，不只查找当前活动思考。Chat 整树显示副本同样装配，以便旧分支展示。

极简行在首个摘要前显示原始首行，之后显示摘要并复用扫动替换动画；相同文字不重播。只有思考的组结束后保留最新摘要；已进入工具阶段的组继续显示工具。展开区域始终使用完整原始思考。

## 费用统计

思考摘要通过 `modules/thinking_summary/billing.py` 按实际 usage 和请求时精确模型价格入账，计入所属对话总花费，明细单列「思考摘要」。格式不合格而未显示的有效请求仍计费；缺少 usage 或单价标记未计价，不补算之前的请求。主模型累计 Token、缓存命中率和 tokens/s 保持原口径，目标模式 Token 限制也不加入摘要请求。完整契约见 `docs/conversation_api_costs.md`。
