# 自动审核上下文与裁决契约

更新：2026-11-07（扩展无限制模式单次完全访问自动审批）。实施计划见 `.astrion/plan/2026-11-06_auto_review.md`。

## 执行边界

- sandbox既有命令分流、只读试运行、权限拒绝后审批及可写重试保持原状。
- direct支持approval／auto_approval／unrestricted；readonly／plan仍锁沙箱。前两种在每条run_command、terminal_input执行前审批，通过后直接在宿主机执行，不做沙箱试跑。
- 显式切入direct显示风险确认；用户级“不再提示”仅确认后保存，恢复已有direct不重复弹窗。
- 单次full_access不同于direct_execution：前者签发一次性grant；后者审核已在direct环境中的调用，不重复签发单次提权。
- `allow_auto_approve_full_access`默认false，适用于auto_approval与unrestricted模式下显式单次full_access请求。关闭仍允许申请：auto_approval需自动与人工均通过，unrestricted仅人工审批；开启时两者均由审核智能体批准即可执行，无需人工。approval始终人工审批。普通unrestricted沙箱调用和已在direct环境的普通命令继续免审。批准条件在请求创建时快照，两处审批派发均读取请求的auto_review_required。
- 人工先通过不能取消必需的自动审核。人工模式不受上述开关影响。标签黄点只表示尚未完成人工决定，不表示纯自动审核运行。

## 送审内容

主模型隐藏思考、system提示词和助手解释不整体转发。送审user内容为紧凑纯文本，不使用JSON包装，不以删减有效信息换取短文本。

1. 普通用户消息、运行引导、ask问题＋选项＋实际回复：三类合计最近5条。
2. 已批准计划及用户意见：有则固定提供。保存批准时计划正文；存量记录缺正文则明示，不读取当前文件冒充已批准版本。
3. 当前用户目标：读取目标状态的goal原文，不把目标审核续接当用户输入。
4. 本次工作触发消息：固定提供，保留实际来源。压缩续接使用原工作锚点。与近期窗口重合时不重复正文。
5. 普通工具历史：最近5个调用＋结果配对，参数和结果保持完整；已单列的问答与计划批准不重复计入。失败、拒绝、取消、后台启动与完成不能混淆。
6. 待审调用单列；同批尚未产生结果的当前或后续调用不作为已执行历史。

同一当前工作目录不重复写；历史调用的不同目录必须保留。序号与缩进表达顺序和结构，不给模型附长message_id／tool_call_id。JSON只用于程序解析原始工具数据和内部指纹，不作为送审或历史补查的包装格式。

### 消息来源

- `guidance`虽带`is_auto_generated=true`仍是受认证用户追加指令，优先读取`runtime_guidance_original`。
- skill、附件路径通知、子智能体／后台命令／工作流通知、压缩续接和模式漂移不是用户新授权。附件按所属输入关联。
- 当前Chat真实输入可能缺message_source，兼容无注入／隐藏标记的普通输入；明确系统通知不可误认。
- ask／plan以原始内置工具调用与匹配的受信结果识别，不采信任意工具输出声称的用户同意。
- 压缩仅标deep_compacted，原始记录仍可按正常分类读取。
- 当前任务尚未消费的用户引导只读快照，不消费队列、不混入草稿恢复来源，并标记“尚未交主模型”。

## 审核工具与政策

- 政策唯一文本：`modules/approval_policy.py`，保留授权、证据可信度、复合命令实际效果、外部代码及调查原则。工具能力本来不允许的操作，不在提示词重复罗列禁令。
- `run_command`继续以独立只读沙箱取证，不继承主对话direct。
- `read_review_history`补查本次冻结的同一对话历史，支持关键词、offset与count（1–20），由近及远返回纯文本；不读取其他会话或任意文件。
- 正常决策仍为approved／rejected＋简短理由，不增加needs_human。证据不足时自动查证，风险拒绝交主模型调整实质方案，不以改写命令或间接执行绕过。
- 审核请求继续统一APIClient、固定思考及review_agent费用入账，conversation_id不可遗漏。

## 故障、人工与输入变化

- 可重试的调用超时／连接／服务故障最多额外重试一次；配置、无有效裁决等失败不假称风险拒绝。
- 审核故障返回decision=error和具体code；审批记录收束为expired并保存auto_review_status=error，操作不执行，不新增人工回退。前端显示“审核失败”而非“用户拒绝”。
- 单次full_access关闭免人工开关时仍按用户选择保留人工步骤，不因引入自动审核新政策而取消。
- 审核绑定已接收用户输入、目标和执行条件的指纹。审核期间变化自动重审一次，持续变化则本次失败关闭；批准后领取权限及工具启动前再次检查，变化则不执行并要求按新输入重审。
- 人工主动裁决、取消和停止继续使用现有流程；未知或过期批准不能签发执行权限。

## 代码归属

- `approval_context_text.py`：来源分类、原始结果解析、紧凑文本。
- `approval_history.py`：5条用户／5条工具窗口、固定计划／触发消息和只读补查。
- `approval_request.py`：输入快照、当前目标、执行条件、文本请求及输入指纹。
- `approval_agent.py`：审核工具与模型轮次；`auto_approval_service.py`：自动审核接续；`full_access_review.py`：双批准与单次授权汇合。
- `tool_approval_manager.py`／`tool_execution_authority.py`：批准状态、参数绑定、单次领取与过期依据校验。
