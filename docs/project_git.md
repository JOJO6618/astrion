# 项目 Git 记录与自动评审

首批功能：浏览进入时当前工作区内的本地 Git 仓库，查看提交历史与历史 diff，并在该工作区启动普通评审对话。页面入口为左侧侧边栏「工作流」下面的「项目 Git」，路由为 `/git?workspace_id=<当前工作区>`。入口使用本地官方 Git 图标，视觉尺寸 17px，沿用侧栏统一热区。

## 使用

1. 进入「项目 Git」，在顶部下拉中选择当前工作区内的仓库。刷新仅重新扫描当前工作区。
2. 点击「选择提交」打开提交面板，选择分支或搜索提交说明；选择提交后收起面板。合并提交可以选择父提交；首次提交与空树比较。SHA 以短码显示，复制按钮复制完整 SHA。
3. 文件导航默认展开，按目录组织变更文件；通过文件数左侧的文件夹按钮展开或收起。在右侧「统一 / 左右」之间切换，切换文件保留视图模式；长 diff 可以继续加载。
4. 在提交面板中切换到分支比较，选择基准分支和目标分支，查看从共同祖先到目标版本的改动。
5. 点击「自动评审」，系统在当前工作区新建普通对话，自动发送包含仓库目录、完整目标 SHA 和基准 SHA 的 review 请求，随后进入该对话。
6. 返回项目 Git 页面，点击「评审记录」打开同一比较范围下的评审对话菜单，选择具体对话后跳转。

Git 是无应用侧栏的独立全屏页。仓库下拉选项使用 6px 圆角 hover、4px 条目间隔；提交列表保留直角 hover，选中不显示左侧竖线。仓库菜单与提交面板双向互斥，提交面板采用 220ms 滑动和淡入淡出，退出动画结束后才移除 DOM；退出期间的新菜单请求也必须维持互斥。尊重系统减少动态效果设置。

提交说明只占一行；存在额外正文或一行溢出时，左侧紧贴标题显示一个无 hover 的展开符号，在下面浮层展示完整 message。评审记录按钮不显示数量，菜单使用真实对话标题、状态与时间；两个浮层都不改变页面布局。文件开关中心与上方作者头像中心同为距左侧 32px；模式切换组的右侧留白为 16px。

评审会话初始为 `execute + readonly + sandbox`：直接开始调查，以只读方式取证。模型沿用当前会话选择，未选时使用目标工作区默认模型；无可用模型时提示错误。需要改代码时，在评审对话中由用户后续授权并调整权限。

点击评审时，如果目标工作区有活动主任务，提示忙碌，不新建评审对话、不排队。本功能的检查不改变其他任务入口原有的并发规则。

## 范围与限制

- 只扫描进入时已确认的当前工作区根目录及其子目录，识别 `.git` 目录和 worktree 的 `.git` 文件；不扫描其他工作区或整台电脑，不跟随目录符号链接。
- 跳过 `.git`、`node_modules`、`.venv`、`venv`、`__pycache__`、`.astrion`、`.codegraph`、`.cache`、`.next`、`.nuxt`。同一真实仓库去重，并保留当前工作区关联。
- 发现结果按工作区身份和路径缓存 60 秒，刷新强制重扫；每次查询重新校验仓库与工作区的归属。
- Git 页面只查询本地对象。本批不包含远端 fetch、GitHub/Gitea PR 接入、checkout、提交和推送操作。
- 普通提交默认与第一父提交比较；分支比较使用 merge base。后续 diff 和评审使用固定完整 SHA，不随分支移动而改变已选范围。
- diff 每次返回最多 1200 行。Git 单次输出超过 32 MiB 或查询超时会明确报错。
- 评审关联索引每仓库保留最近 200 条。任务记录已被回收时显示「已保存」，不据此推断评审成功。
- 自动评审准确性取决于模型调查与取证；提示词要求只报告本次改动引入、有明确证据的具体问题，并说明未验证项。

## 实现与维护约束

- Git 查询权威：`modules/project_git/runner.py`；仓库扫描：`discovery.py`；历史与 diff：`history.py`；关联存储及评审提示词：`reviews.py`。
- Web 蓝图：`server/project_git.py`，在 `server/app_legacy.py` 注册；任务启动和关联查询：`server/project_git_review.py`。
- 前端：`static/src/components/git/`；双语文案：`static/src/locales/{zh-CN,en-US}/git.ts`。
- 查询使用轻量 workspace data/context，不为浏览仓库创建 WebTerminal、容器或复制技能。评审启动走正常 `RuntimeService.create_task`，保持既有门闸、任务事件与对话快照链路。
- 评审会话独立创建，不切换正在使用的 terminal 会话。标题和固定 Git 范围写入会话；关联索引存于 `<工作区 data_dir>/project_git_reviews/<作用域哈希>/<仓库哈希>.json`，原子写入，不落源码目录。
- `/git` 必须前后端双登记。入口离开对话前捕获显式工作区身份；Git 独立路由同样调用 `prepareInitialWorkspaceIdentity`，验证身份并等待串行选择完成，组件收到已提交身份后才扫描。直接打开 `/git` 时使用已确认身份补齐 URL，不猜 `default`；返回无暂存对话时保留工作区参数。
- 所有 `/api/project-git/*` 查询均携带显式 `workspace_id`。发现接口只调用一次单工作区 resolver；仓库详情和评审也只在该工作区内解析，不枚举其他工作区、不使用前端过滤冒充范围限制。
- Git 历史代码通过 `git show SHA:路径` 读取，不能用当前工作树代替历史版本。不要复用工作树状态面板作为历史 diff 数据源。
- 评审列表返回真实对话的 `metadata.title`，复用本次读取的对话数据，不另建标题查询链路。任务缺失仍显示已保存，不把未知状态视为成功。
- 评审启动成功后，关联索引写失败仍返回真实任务身份并附提示，避免重复启动。
- 页面异步请求必须检查归属和卸载状态，迟到响应不得覆盖新仓库或新比较范围。
