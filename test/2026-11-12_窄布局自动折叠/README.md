# 窄对话区自动折叠

2026-11-12：阈值 600px→300px（用户实测觉得偏大，按 CSS 像素计、不含快捷面板列）。对话区宽度低于 300px 时自动折叠面板；取代 `2026-11-10_快捷窗口窄布局` 里“展开后不因宽度折叠”的规则。自动展开的 300px 判定（`autoExpansion.ts`）保持不变。

## 规则

- **折叠对象与顺序**：先收「快捷面板组」，再收「右侧面板组」。快捷面板、文件内容预览、预览窗口三者绑定，一起收（快捷面板折叠本来就会清空文件预览/详情/菜单，预览窗口 `preview.activeKey` 现在也联动关闭，不算用户主动关闭，不抑制后续自动展开）；终端与 Git 变更一起收。
- **手动打开的也折叠**：只要是展开状态就受影响，不区分是自动还是手动打开。
- **强制展开**：用户在空间不足时手动打开（顶部展开按钮、输入栏“X 个子智能体”、打开文件预览/预览窗口、打开终端/Git），该组被标记强制保留，**直到整组被关闭**才失效。空间足够时的手动打开不算强制，之后变窄仍会折叠。
- **单向**：只在变窄时折叠，变宽不会自动展开回来，所以不需要迟滞，也不会反复开合。
- **自动路径同样受限**：预览自动展开（`preview_auto_open`）、终端自动打开（`auto_open_terminal_panel`）放不下时不执行；切换对话回填内容也不自动展开快捷面板（原有规则）。切换对话时终端面板不做特殊处理。
- 每折叠一组后等待 500ms（面板宽度过渡）再复查，第一组收完仍不足才收下一组；拖拽调宽期间（`body` 光标为 `col-resize`）跳过，拖拽结束补查一次。
- 手机不适用。

## 代码

- 纯决策与测量：`static/src/components/chat/quickdock/narrowLayout.ts`（`decideNarrowCollapse`、`hasRoomFor`）。
- 监听与执行：`static/src/app/methods/ui/narrowLayout.ts`（ResizeObserver + window resize，挂在 `lifecycle.ts` 的 mounted / beforeUnmount）。
- 强制标记：`quickDock.quickGroupForced`（快捷面板组）、App 状态 `rightPanelsForced`（右侧面板组）。

离线回归只覆盖决策函数（599／600／601px 边界、折叠顺序、强制保留、阈值与自动展开一致）；ResizeObserver、动画与真实布局需要用户视觉验收。

## 用户视觉验收

1. 打开快捷面板与终端，缓慢拖窄窗口：对话区低于 300px 时先收快捷面板（连带文件预览/预览窗口），仍不足再收终端/Git。
2. 窄布局下手动点击展开按钮：能强制展开，继续拖动窗口不再被收；关闭后恢复规则。
3. 窄布局下切换到有待办/文件的对话，或预览/终端自动打开：不应自动展开。
4. 变宽后不应自动展开回来。
5. 拖动终端宽度手柄时，面板不应在拖动中途被收起。
