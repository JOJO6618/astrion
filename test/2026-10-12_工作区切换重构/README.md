# 工作区切换重构回归

覆盖工作区／对话完整身份、轻量数据查询、运行资源并发、技能准备、草稿顺序和列表缓存。当前包含 40 个测试或场景，全部由主智能体编写；不创建子智能体、不启动后端、不执行真实模型请求。

## 运行

在项目根目录运行，使用已经安装项目依赖的解释器与 Node：

```bash
/opt/homebrew/bin/python3.11 -B test/2026-10-12_工作区切换重构/run_regressions.py
```

分项运行：

```bash
/opt/homebrew/bin/python3.11 -B test/2026-10-12_工作区切换重构/backend.py
/opt/homebrew/bin/python3.11 -B test/2026-10-12_工作区切换重构/layout.py
/opt/homebrew/bin/python3.11 -B test/2026-10-12_工作区切换重构/integration.py
node test/2026-10-12_工作区切换重构/frontend.cjs
node test/2026-10-12_工作区切换重构/startup.cjs
```

原有快照、轮询、消息身份、辅助归属、统一发送守卫、标题同步、固定子权限与费用测试仍须按对应目录运行；这些测试不能替代它们。

## 真实验收边界

离线回归不证明实际切换速度已经达标，也不等于桌面／浏览器视觉验收。新后端代码按正常方式加载、前端构建更新后，由用户实际检查：

1. 首次进入 /new，草稿请求使用服务端返回的真实工作区，不出现虚构 workspace_id=default。
2. 同工作区切对话、跨工作区切对话、单独切工作区分别测量；热对话和未打开过的对话分开记录。
3. 快速连续切换，核对最终工作区、对话、草稿、有效模式和运行任务订阅。
4. 加载期间编辑输入，回到来源工作区检查内容保留。
5. 有运行任务／可恢复子任务的对话另作实际恢复验证。

2026-10-12 用户本机实际验收反馈：没有明显问题，跨工作区加载速度与工作区内切换对话几乎一样。此反馈是定性实测，不代表所有数据规模与平台的量化保证。提交前已移除临时计时接口、请求头、包装器与插桩，计时代码及配套测试存档在本地 `_experiments/workspace-switch-timing-20261012/`，不纳入版本控制；工作区请求绑定与业务回归保留。

原采样日志为 <LOGS_DIR>/workspace_switch_timing.log，统一前缀 [workspace-switch-perf]，现只保留历史证据。view.ready 是状态提交，帧回调不代表全部内容绘制完成；诊断收集窗口不属于用户等待。
