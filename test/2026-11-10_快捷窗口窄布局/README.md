# 快捷窗口窄布局自动展开

规则：桌面快捷窗口预计展开后，对话区域至少保留 300px（2026-11-12 由 600px 调整），才允许自动展开。完整占位宽度读取 `.quick-dock` 的 `--qd-expanded-width`（当前 294px）；实际对话宽度会包含侧边栏、浏览器、文件预览与终端面板占位的影响。

- 首次挂载、内容出现／切换回填、自动展开设置开启及设置首次就绪都检查实际空间。
- 未挂载、无有效宽度时先收起；挂载测量后再决定。
- ~~只检查自动展开入口，不监听宽度来强制折叠已打开面板。~~ 2026-11-12 起被取代：窄对话区会自动折叠，见 `test/2026-11-12_窄布局自动折叠/README.md`。
- 手动展开按钮和“子智能体”查看入口保持可用。
- 手机快捷窗口由用户打开整层，不作为桌面占位列处理。

## 离线回归

需要 Node 24（支持直接加载 TypeScript）和已安装的项目依赖：

```bash
node --test test/2026-11-10_快捷窗口窄布局/auto_expansion.test.mjs
npm run build --silent 2>&1 | tail -n 5
```

回归覆盖 299／300／301px 的边界、展开动画中预算一致性、侧面板占位、CSS 列宽变化、缺失测量，以及组件真实状态同步函数的设置／手动展开行为。DOM 尺寸由离线夹具提供，不代表真实界面视觉验收。

## 用户视觉验收

1. 展开浏览器等面板，使收起时对话区不足 594px；首次加载、切换对话或产生待办／文件记录都不应自动展开快捷窗口。
2. 同样的宽度下，切换“快捷窗口自动展开”为开启，面板仍应收起。
3. 主动点击右上展开按钮或输入栏的子智能体入口，应能展开。
4. （已被 2026-11-12 新规则取代：展开后继续拖窄，面板会自动折叠；强制展开的除外。）收起后新内容到达时不应重新自动展开。
5. 恢复足够宽度后，再触发内容出现，自动展开设置开启时应允许展开；动画中不应反复开合。
