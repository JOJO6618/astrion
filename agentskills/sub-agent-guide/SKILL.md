# 子智能体使用指南

## 划定任务与责任

子智能体是可持续协作的命名实例。完成一轮后默认保留idle，后续优先复用已有实例及其上下文；暂时没有新任务时无需采取操作。

把一个清晰的独立任务交给合适的已有实例，确需新实例时再创建。先自行浅查项目或信息来源，再给出目标、背景、文件范围、完成标准和需要的最终答复。子实例不自动看到主对话历史，必要上下文必须写进task或后续消息。

主要逻辑、架构和协调工作由主智能体承担。未经用户明确授权，不把主要代码交给子智能体。对获准的修改任务划定互不重叠的目录／文件，避免多个实例和主智能体同时写同一模块。最终由主智能体读改动和验证证据，不能把子回复直接当已验证结论。

优先并行彼此独立的探索、资料收集、文档和测试任务。对依赖前一项结果的工作，等收到明确结果后再派发下一项，或使用已有实例继续；不要靠延时或文件轮询猜测完成。

## 命名与创建

使用当前工具schema。所有子智能体后台运行，创建立即返回，后续每轮只把最终回复作为user消息通知主对话。普通中间输出留在子活动记录，不会自动灌入主上下文。

```json
{
  "name": "AuthResearch",
  "summary": "定位登录偶发失败",
  "task": "阅读src/auth和src/middleware，定位可能的500错误路径。仅分析，不修改代码。最终回复列出证据、文件位置和不确定性。",
  "intelligence": "same",
  "access_level": "working_dir_write",
  "working_dir": "analysis/auth",
  "timeout_seconds": 900
}
```

调用create_sub_agent时传上述参数，不要传agent_id、role_id、deliverables_dir或run_in_background。工具需要的intent按当前schema填写。

- name同一对话内大小写不敏感唯一，1–80字符；不能含控制字符、标签或路径分隔符。名称终结后也不复用。
- intelligence选same/high/medium/low，分别使用当前模型或用户配置的相应模型。
- working_dir省略时自动创建新目录；可指定或复用项目内目录。它是真实的默认cwd和相对文件路径基准，不是强制交付目录。
- timeout_seconds可省略，省略本轮不限时。不是创建后永久有效的总寿命限制。
- 不要求创建文件或调用结束工具。只需分析的任务可直接给最终答复。

## 选择固定内置权限

| access_level | 内置工具写入范围 |
| --- | --- |
| working_dir_write | 仅该子工作目录 |
| workspace_write | 当前项目工作区 |
| sandbox_write | 当前工作区＋沙箱授权可写路径 |
| full_access | 宿主完全访问，需当前权限及平台允许 |

按任务选择足够的最小档位。工作区身份始终是原项目，working_dir只改变相对路径／默认cwd与窄档写根。恢复不能通过重新解析目录扩大权限；父权限变化不改变已创建子档位。

MCP为外置插件，不套此表的内置工具目录写沙箱。子实例使用独立MCP客户端，只装配父可见且未禁用工具；默认Playwright profile按子实例隔离，显式共享配置仍可能共享外部状态。不要把独立连接理解成任意外部服务都有隔离能力。

## 接收结果并继续

无需调用sleep等待子智能体。结束主回复后系统仍能在子实例完成时插入结果消息；有独立工作则可继续处理，避免反复查状态或输出无意义的等待内容。

收到一轮结果后核实证据。需要继续分析、修正或追加任务时，向原name发送消息：

```json
{
  "name": "AuthResearch",
  "message": "沿用刚才的代码位置，进一步核对异常处理分支；最终列出可复现的最小触发条件。",
  "timeout_seconds": 600
}
```

send_message_to_sub_agent会保留原上下文；实例不在内存且未终结时先按新格式历史恢复，已终结实例无法恢复。空闲时消息开启新轮；运行中消息在完整工具批次后的安全边界作为引导，不重置当前预算。新轮省略timeout_seconds表示不限时。

用get_sub_agent_status(names=[...])查询指定实例；省略names查询当前主对话全部已创建实例，包括idle和terminated。主、子智能体使用同一查询工具，结果统一为results数组。工具结果不返回task_id或conversation_id，后续操作只使用name。不要为同一个已有实例换名称重新创建来冒充恢复。

## 理解轮次结束与暂停

自然最终回复后进入idle，保留消息、模型、工作目录、权限和累计用量。idle不是失败，也不算持续运行。默认让实例保持idle，不用调用stop或terminate收尾；本轮任务完成、主智能体准备最终回复、当前暂无后续工作，都不是终结理由。

例如：AuthResearch交回分析结果后，主智能体核实并完成当前答复，AuthResearch继续保持idle；以后需要补充分析时，直接向原name发送消息。

预算到期时，当前模型响应正常接完；该响应产生的整批工具全部执行，真实结果完整回填；只在下一次模型请求前暂停并通知。不要期待预算立刻取消耗时工具或问答。后续可发消息继续原实例。

- stop_sub_agent：立即请求取消当前响应或工具，保留上下文并进入idle，可继续。已提交批次的缺失结果标为“被主智能体取消”，已完成结果保留；未提交的半截调用丢弃。与预算到期的完整批次规则不同。
- 停止后保留未消费的排队消息，但暂停自动消费；需要继续时显式向原name发送新消息。取消不代表撤销已发生的文件写入或外部操作。
- terminate_sub_agent：永久终结，无法再次激活，文件和历史保留。仅在用户明确要求、经核实实例发生无法恢复且无法继续使用的错误，或严重违反明确指令且纠正后仍继续偏离时，才可终结；实际达到实例上限、已有实例无法复用且确需新建时，也可终结不再需要的空闲实例。不要例行清理、批量终结已完成实例或预防性释放名额。
- 不可恢复错误：例如上下文或实例状态损坏，导致无法恢复或续接。先核实错误和实例状态；普通报错、可恢复故障、理解偏差或意见分歧不构成终结理由。网络中断、超时或单次任务失败，能够纠正或重试时仍优先保留原实例。
- 严重偏离指令：明确违反任务范围、权限或约束，且纠正后仍继续偏离时，可以终结。发现正在或即将执行未经授权的破坏性操作时，立即stop_sub_agent，不必等待纠正；无法可靠继续协作时再terminate_sub_agent。停止和终结不能撤销已发生的操作，应核对实际影响。
- 网络／模型失败：读最终通知和end_reason，先核实原因；保留上下文可用时发消息重试。
- 真实进程中断后的缺失工具结果会标为未知，应核对实际外部状态，不能假设失败就没有副作用。

## 主子和子子问答

子实例可用ask_master向主提问。主收到包含question_id的问题时，用answer_sub_agent_question回填；问答工具本身会等待答案。不能等所有子实例空闲后才回答。

子实例可按name用ask_other_agent提问，接收方通过answer_other_agent配对question_id，或按该提问给出最终回复。子子提问和答复同时汇报主对话。所有协作仍要遵守已划定的文件写入范围，通信能力不意味着可以同时修改同一文件。

## 验证与汇报

分别说明子实例做了什么、产出了什么证据、主智能体实际复核了什么。仅收到完成通知不等于任务验收；文件修改需要检查差异及相关测试，资料结论需要核对来源。不能把idle、超时通知或空回复当作所有要求已完成。
