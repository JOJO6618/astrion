# Media Toolkit

先确认用户要保留的内容与可接受的变化：尺寸、时长、画幅、画质、透明度、音轨、字幕、文件大小或目标平台。参数能从原文件和请求确定时直接执行；只有会明显改变作品的问题才提问。保留原文件，生成有明确名称的新输出。

## 检查真实环境和输入

用 `run_command` 探测 FFmpeg、ffprobe 与可用 Python，不假设全局预装。需要图像处理时再检查该解释器的 Pillow。按项目已有环境准备所需依赖，不为一次裁切安装完整视频创作框架。

```bash
ffmpeg -version
ffprobe -version
ffprobe -v error -show_format -show_streams -of json input.mp4
```

检查实际流：编码、尺寸、旋转元数据、帧率与可变帧率、时长、像素格式、色彩空间/传递函数、音轨语言与声道、字幕格式。不要只根据扩展名判定格式，也不要用文件大小推断画质。记录输入/输出路径；路径含空格时正确引用，参数作为独立参数传递，不能把用户文件名拼成可执行 shell 片段。

输出放工作区，如 `output/media/`。命令示例中的文件名和滤镜参数必须替换为真实路径与目标要求。使用 `-n` 避免无意覆盖；同名输出需要更新时先明确该文件属于本任务。

## 选择最少损失的处理方式

- 只换封装且编解码器兼容目标容器：优先 `-c copy`，不改变画质。
- 要求精确到帧的剪辑、缩放、调色、字幕烧录：需要解码再编码。
- `-c copy` 的切点受关键帧约束，可能不精确；不能把快速粗剪当精确剪辑。
- 不为“变清晰”盲目放大；保留原始分辨率和科学/医疗图像的真实细节。
- HDR、广色域、10-bit、透明通道和多音轨不能按普通 SDR H.264 静默处理。先确定目标播放环境与是否允许转换。

## 常用视频流程

### 精确片段

```bash
ffmpeg -n -i input.mp4 -ss 00:00:05.000 -t 00:00:12.000 \
  -map 0:v:0 -map '0:a:0?' -c:v libx264 -crf 20 -preset medium \
  -pix_fmt yuv420p -c:a aac -b:a 160k -movflags +faststart output/clip.mp4
```

此例面向普通 SDR 兼容交付，会重编码。检查输出首尾帧和时长。没有音轨时可选映射不会报错；如有多音轨/字幕需求，按需求显式映射，不能宣称所有流已保留。

### 缩放与画幅

等比例缩到不超过 1280×720，并保持编码器要求的偶数尺寸：

```bash
ffmpeg -n -i input.mp4 \
  -vf "scale=1280:720:force_original_aspect_ratio=decrease:force_divisible_by=2" \
  -c:v libx264 -crf 20 -c:a copy output/resized.mp4
```

只有输入音轨能封装进目标 MP4 时才 `-c:a copy`。目标不兼容时明确选择转码。竖屏裁切先确定主体位置；不要默认居中截掉人脸、字幕或图表。留边和裁切是不同交付选择，不能无说明互换。

### 拼接

同编码、分辨率、时间基和相容音轨的文件可用 concat demuxer；异构输入先规范化或使用 concat filter。不要只看后缀相同就 `-c copy`。文件清单由脚本安全生成并逐行检查，特别处理单引号与换行路径；不把用户文本当清单指令。拼接后检查连接处画面、时间戳与音画同步。

### 封面与联系表

```bash
ffmpeg -n -ss 00:00:02 -i input.mp4 -frames:v 1 output/cover.png
ffmpeg -n -i input.mp4 -vf "fps=1/10,scale=240:-1,tile=4x3" \
  -frames:v 1 output/contact-sheet.jpg
```

联系表例子最多展示前 12 个十秒采样帧。要覆盖整片，根据探测时长计算等距采样并标注时间；不要把片头样本当全片验收。用 `view_image` 检查需要关注的帧。

### 字幕

先识别字幕编码、时间轴和语言。软字幕保留可切换性，烧录则变为画面像素。FFmpeg `subtitles` 滤镜有独立于 shell 的转义规则；复杂路径先复制到本任务安全工作目录或用正确的滤镜转义，不能靠给 shell 路径加引号解决所有问题。烧录 CJK 前验证字体和字形，检查行宽、底部安全区和相邻字幕时间。

### GIF 与动画 WebP

GIF 适合短循环、低帧率和有限颜色。长视频优先交付 MP4/WebM。高质量 GIF 先生成 palette 再 paletteuse；控制时长、宽度和帧率，不能承诺大画面/长时长同时只有极小文件。WebP 导出检查循环次数、透明背景和目标平台支持情况。

## 音频

提取无损处理中间文件：

```bash
ffmpeg -n -i input.mp4 -map 0:a:0 -vn -c:a pcm_s16le output/audio.wav
```

这是 PCM 转换，不等于恢复输入已经丢失的信息。语音任务常用 mono/16kHz，但音乐或保真交付不能静默采用该规格。保留需要的声道布局和采样率。

响度标准化按目标平台指定 LUFS/true peak；严谨交付用 `loudnorm` 两遍测量，第二遍填入第一遍的实际 measured 值。不能复制虚构测量值。降噪先听代表性样本，避免损害人声与音乐瞬态；没有听检工具时明确只做了可验证的技术检查。

## 图片与批量处理

Pillow 适合裁切、缩放、旋转、格式转换与拼图。读取后先按 EXIF 方向转正，再计算裁切框；缩小用合适重采样。检查透明通道、ICC 和 EXIF 的保留/移除要求：JPEG 不支持透明，需要用户认可的背景色；转成 RGB 也不等于已正确完成 ICC 色彩转换。

批量任务先列出输入与输出命名规则，跳过输出目录，避免重复处理自身结果。对尺寸异常、损坏图片或动图逐文件报告，不静默截成第一帧。超大图要考虑内存和 Pillow 解压限制；不要全局关闭保护来吞下未知输入。

## 验证与交付

1. 确认工具正常退出且输出文件存在、非空；FFmpeg 常把正常进度写到 stderr，不以 stderr 非空判失败。
2. 用 ffprobe 复查目标时长、尺寸、编码、轨道数量、帧率及音频参数。对需要严格解码验证的输出，用 `ffmpeg -v error -i output.mp4 -f null -` 检查解码错误。
3. 检查代表性帧，尤其首尾、切点、字幕与透明边缘；视觉验收遵守工作区规定。音画同步与听感不能仅靠元数据证明。
4. 图片用 `show_image`，文档/媒体文件用 `show_file` 或工作区相对 `download://` 链接交付。需要可重复流程时一并提供实际命令或脚本。
5. 说明做了哪些转换、输出规格和已执行检查；文件生成不等于全片画质、听感或所有设备兼容性均已通过验收。
